# 《尺素 Letters & Longing》开发任务文档

版本：V1.0  
状态：生产实施版  
用途：执行拆解、排期和验收

---

## 1. 执行原则

项目以“可上线的静态内容站”为第一目标。所有任务围绕内容质量、页面体验、静态构建和 SEO 展开。

执行原则：

1. 先搭建稳定工程，再扩展页面；
2. 先确定数据结构，再填充内容；
3. 内容研究与数据整理由 Codex 完成，不建设 Excel / CSV 导入链路；
4. 构建时用脚本校验数据质量和版权规则；
5. UI/UX 以阅读、检索和复制效率为核心；
6. 不做用户系统、后台系统、AI 写作和在线投稿。
7. 当前阶段不引入数据库，所有内容使用 JSON / MDX 文件存储。
8. 首版内容只做公版公开信和本站整理，不做原创书信或现代仿写。

---

## 2. 阶段一：工程与视觉基础

目标：

```text
建立可运行、可构建、可部署的 Next.js 静态站基础。
```

任务：

1. 创建 Next.js App Router 项目；
2. 配置 TypeScript、Tailwind CSS、ESLint；
3. 建立基础目录：`app/`、`components/`、`data/`、`content/`、`lib/`、`scripts/`；
4. 建立全站布局：页头、导航、页脚、主内容容器；
5. 建立基础 UI 组件：按钮、输入框、标签、短句卡片、信件卡片、专题卡片；
6. 建立设计 token：颜色、字体、间距、圆角、阴影、focus 状态；
7. 建立移动端优先的响应式布局；
8. 接入基础 SEO 元信息；
9. 确认文件存储方案：`data/*.json`、`content/**/*.mdx`、`public/search-index.json`；
10. 完成 Cloudflare Pages 构建配置。

交付物：

```text
可本地运行、可静态构建、可部署的项目骨架。
```

验收标准：

1. `npm run dev` 可启动；
2. `npm run build` 可通过；
3. 首页、关于页和基础布局可访问；
4. 移动端 360px 宽度无横向滚动；
5. 基础按钮、链接、输入框有可见 focus 状态；
6. 项目不包含后台、登录、导入接口或数据库依赖；
7. 内容数据可以从文件读取并参与静态构建。

---

## 3. 阶段二：数据结构与内容校验

目标：

```text
建立生产级文件数据模型和构建前校验机制。
```

任务：

1. 定义 `letters.json`、`excerpts.json`、`tags.json`、`topics.json`、`sources.json`；
2. 定义 TypeScript 数据类型；
3. 建立内容读取工具；
4. 编写 `validate-data.ts`；
5. 校验 ID、slug、引用关系、必填字段、版权状态、发布状态；
6. 确保 `draft` 内容不进入页面、搜索索引和 sitemap；
7. 准备少量 seed 数据用于页面开发；
8. 建立内容错误输出格式，方便定位到具体文件和具体条目。
9. 记录数据库暂不引入的边界：无用户写入、无后台编辑、无实时查询需求。

交付物：

```text
可被页面消费、可被构建校验的数据层。
```

验收标准：

1. 数据类型清晰；
2. 引用错误会导致校验失败；
3. 未发布内容不会进入前台；
4. 公开信和摘录缺少来源时会导致校验失败；
5. 页面可以通过统一工具读取数据，不在组件中散落 JSON 解析逻辑。
6. 文件数据规模能够覆盖 MVP 和 V1 目标，不需要数据库即可发布。

---

## 4. 数据库评估节点

目标：

```text
明确什么时候继续使用文件，什么时候才考虑数据库。
```

当前结论：

```text
MVP 和 V1 均使用文件存储，不建设数据库。
```

原因：

1. 内容低频更新；
2. 无用户写入；
3. 无后台管理；
4. 数据规模可控；
5. 文件可被 Git 审查和回滚；
6. 静态构建更适合 SEO 和低成本部署。

后续只有出现以下情况，才重新评估数据库：

1. 开放用户投稿、收藏、评论或个人内容；
2. 需要后台在线编辑和多人审核；
3. 内容需要高频在线发布；
4. 数据达到数万条以上，本地搜索或静态构建明显吃力；
5. 需要复杂查询、权限控制或实时个性化推荐。

该节点不是当前开发任务，只作为未来架构升级边界。

## 5. 阶段三：核心页面开发

目标：

```text
完成 MVP 所需的主要页面和浏览路径。
```

任务：

1. 首页：品牌区、主搜索入口、今日推荐、关系入口、专题入口；
2. 开头馆：短句列表、搜索、筛选、复制、详情跳转；
3. 结尾馆：短句列表、搜索、筛选、复制、详情跳转；
4. 情谊分类页：推荐开头、推荐结尾、相关信件、相关专题；
5. 世界书信馆：信件列表、筛选、详情跳转；
6. 书信详情页：元信息、背景、正文、摘录、来源、相关内容；
7. 短句详情页：原文、解释、改写、场景、标签、来源、相关短句；
8. 专题列表与专题详情页；
9. 关于页：产品说明、内容原则、版权说明。

交付物：

```text
MVP 页面闭环。
```

验收标准：

1. 所有页面 URL 可访问；
2. 列表页能正确展示 published 内容；
3. 详情页能处理不存在的 slug / id 并返回 404；
4. 复制操作有成功反馈；
5. 筛选条件可清除；
6. 空状态有推荐操作；
7. 移动端和桌面端信息层级清晰。

---

## 6. 阶段四：搜索、SEO 与构建产物

目标：

```text
让网站可检索、可收录、可传播。
```

任务：

1. 编写 `build-search-index.ts`；
2. 接入 Fuse.js；
3. 实现首页全站搜索；
4. 实现列表页局部搜索和筛选；
5. 编写 `build-sitemap.ts`；
6. 生成 `robots.txt`；
7. 为首页、列表页、详情页、专题页生成 meta title / description；
8. 增加 Open Graph 信息；
9. 增加短句和信件详情页结构化数据；
10. 编写 `check-source-links.ts` 用于来源链接抽检。

交付物：

```text
具备基础 SEO 和搜索能力的可发布版本。
```

验收标准：

1. 搜索结果能返回短句、信件和专题；
2. 搜索输入有 debounce；
3. sitemap 不包含 draft 内容；
4. 每个详情页有唯一标题和描述；
5. 来源链接检查可输出失败列表；
6. 构建流程自动生成搜索索引和 sitemap。

---

## 7. 阶段五：内容研究与数据生产

目标：

```text
由 Codex 完成第一批真实内容研究、整理和结构化。
```

任务：

1. 确定第一批内容选题和来源范围；
2. 搜集可发布的公版公开信、开放授权文本或合理短引用；
3. 为每封信整理标题、作者、收信人、时间、背景、摘要、来源和版权状态；
4. 从信件中拆分开头、结尾和正文短句；
5. 为短句补充翻译、白话解释、关系标签、情绪标签和使用场景；
6. 输出 `letters.json`、`excerpts.json`、`sources.json`、`tags.json`；
7. 输出 5 个专题的 MDX 内容；
8. 运行数据校验并修复问题；
9. 替换开发 seed 数据。

MVP 内容指标：

```text
50 封信
200 条短句
20 - 40 个标签
5 个专题
```

验收标准：

1. 每条内容都有清晰来源说明或本站整理说明；
2. 历史原文、翻译、整理、白话解释区分明确；
3. 不确定版权或出处的内容不发布；
4. 短句有可用场景和标签；
5. 内容能通过校验脚本；
6. 页面展示无明显空字段或占位文案。

---

## 8. 阶段六：UI/UX 打磨

目标：

```text
让网站达到可公开发布的阅读和交互质量。
```

任务：

1. 优化首页首屏：品牌感、搜索入口和主要分类同时可见；
2. 优化短句卡片：原文、解释、标签、复制、详情入口层级清楚；
3. 优化信件详情页：正文阅读宽度、段落间距、来源说明位置；
4. 优化筛选区：移动端可折叠，桌面端可快速扫描；
5. 优化空状态、加载状态和复制成功反馈；
6. 检查 hover、focus、pressed、disabled 状态；
7. 检查色彩对比度；
8. 检查移动端 360px、768px、1024px、1440px 视口；
9. 检查键盘导航和屏幕阅读器标签；
10. 检查 reduced motion。

验收标准：

1. 正文阅读舒适，桌面端长文本不满屏铺开；
2. 所有主要交互有反馈；
3. 所有图标按钮有可访问名称；
4. 不依赖颜色单独表达状态；
5. 无横向滚动、文本溢出和按钮文字挤压；
6. 视觉风格统一，不出现过度装饰或层层卡片。
