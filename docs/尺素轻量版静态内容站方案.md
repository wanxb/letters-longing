# 《尺素 Letters & Longing》轻量版静态内容站方案

版本：V0.2  
方向调整：不做用户上传、不做 AI 写作、不做后台系统  
核心目标：用最低成本做一个高审美、高质量、可持续维护的书信短句内容网站

---

## 1. 方向调整结论

原方案中包含：

- 用户上传；
- 家书投稿；
- AI 写信助手；
- 后台内容管理；
- 审核流程；
- 权限系统；
- OCR；
- 文件存储；
- 数据库；
- 搜索引擎。

这些功能会显著增加开发成本、运维成本、隐私风险和合规复杂度。

现在调整为：

> **只做一个精美的前端内容站 + 一套高质量可维护的数据集。**

也就是：

```text
静态网站
  + 书信短句数据
  + 公开信件数据
  + 标签筛选
  + 本地搜索
  + SEO 页面
  + 内容采集与整理流程
```

---

## 3. 推荐技术架构

## 3.1 最推荐方案

```text
前端框架：Astro 或 Next.js 静态导出
UI：React 组件 + Tailwind CSS
数据：Markdown / MDX / JSON
搜索：Fuse.js 本地搜索
部署：Cloudflare Pages
版本管理：GitHub
内容维护：本地表格 / JSON / Markdown
```

---

## 3.2 两个可选技术路线

## 方案 A：Next.js 静态站

```text
Next.js
React
TypeScript
Tailwind CSS
本地 JSON / MDX
next export / 静态生成
Cloudflare Pages
```

### 优点

- 当前 Demo 是 React，迁移成本低；
- 你熟悉前端项目逻辑；
- 后续如果要升级动态功能，也方便；
- 组件化能力强；
- 适合做筛选、搜索、卡片交互。

### 缺点

- 对纯内容站来说略重；
- Next.js 部署到 Cloudflare 时需要注意静态导出配置；
- 如果完全不要服务端能力，Next.js 的优势没有完全发挥。

### 适合情况

如果我们希望基于现有 React Demo 继续开发，选 Next.js。

---

## 方案 B：Astro 内容站

```text
Astro
React Islands
Tailwind CSS
Markdown / MDX Content Collections
Fuse.js
Cloudflare Pages
```

### 优点

- 天然适合内容站；
- 静态输出非常干净；
- SEO 友好；
- 页面性能好；
- Markdown 内容管理舒服；
- 可以局部使用 React 组件。

### 缺点

- 需要熟悉 Astro；
- 现有 React Demo 需要改造；
- 如果后续转动态系统，需要重新规划。

### 适合情况

如果我们确定长期就是内容站，选 Astro 更优雅。

---

## 3.3 最终建议

考虑到我们已经有 React Demo，建议：

> **第一版用 Next.js 静态站。**

原因：

1. 当前 Demo 可以直接迁移；
2. 交互筛选和搜索用 React 很方便；
3. 后续如果想增加简单接口，还能扩展；
4. 部署到 Cloudflare Pages 或 Vercel 都方便。

长期如果完全确定只做内容站，也可以再考虑 Astro。

## 8.4 内容转换脚本

建议准备脚本：

```text
/scripts
  csv-to-json.js
  validate-data.js
  build-search-index.js
  check-dead-links.js
```

### csv-to-json.js

作用：

```text
把 Excel 导出的 CSV 转成前端使用的 JSON
```

### validate-data.js

作用：

检查：

1. id 是否重复；
2. letterId 是否存在；
3. copyrightStatus 是否为空；
4. publishStatus 是否为 published；
5. 必填字段是否为空；
6. 短句是否有关联标签；
7. 来源是否填写。

### build-search-index.js

作用：

```text
生成 search-index.json
```

### check-dead-links.js

作用：

```text
检查来源链接是否失效
```

## 9. 版权控制方式

虽然没有后台审核，但必须有数据规则。

### 9.1 版权状态

```text
PublicDomain：公版
OpenLicensed：开放授权
Quotation：短引用
Original：本站原创
UserAuthorized：用户授权，暂不使用
Unknown：未知，不发布
```

### 9.2 发布规则

构建脚本中强制：

```text
copyrightStatus = Unknown 的内容不进入前台
publishStatus != published 的内容不进入前台
sourceUrl 为空且 sourceType 不是 Original 的内容不进入前台
```

这样即使没有后台，也可以靠脚本避免错误内容上线。

## 15. 为什么这个方向更适合现在

### 15.1 成本最低

不需要服务器、数据库、AI、后台。

### 15.2 风险最低

没有用户上传，就没有隐私数据；没有 AI 生成，就不会伪造历史内容；没有后台，就少很多安全风险。

### 15.3 开发最快

当前 Demo 可以直接变成静态网站。

### 15.4 更符合产品本质

这个项目最核心的价值本来就是：

```text
内容审美
来源可信
短句整理
书信情感分类
```

不需要一开始就做复杂平台。

### 15.5 后续仍可扩展

如果未来真的有用户和流量，再考虑：

- 后台；
- 数据库；
- 投稿；
- AI；
- 搜索服务。

现在不做，不代表永远不能做。
