# 《尺素 Letters & Longing》产品文档

版本：V1.0  
状态：生产实施版  
产品定位：静态书信美学内容站

---

## 1. 产品目标

《尺素 Letters & Longing》是一个围绕书信表达、公开书信和情感短句建立的静态内容网站。第一版的目标不是做平台，而是做一个可上线、可收录、可持续扩展的高质量内容产品。

核心目标：

1. 建立可信、优雅、可检索的书信短句库；
2. 建立公开书信精选与出处说明；
3. 用专题页承接长尾搜索和内容传播；
4. 用静态架构降低开发、部署和维护成本；
5. 让用户在浏览、查找、复制和阅读中获得稳定、克制、有质感的体验。

一句话定位：

```text
一个面向中文用户的书信美学资料库，用精选内容、清晰来源和优雅阅读体验，帮助用户找到合适的书信表达。
```

---

## 2. 用户与场景

主要用户：

1. 想写信、卡片、明信片、留言但不知道如何开头或结尾的人；
2. 喜欢书信文学、公开信、历史文本和情感表达的人；
3. 需要引用、改写或学习书信表达的创作者、学生和内容编辑；
4. 通过搜索引擎寻找“情书开头”“家书结尾”“英文书信问候”等具体答案的用户。

核心场景：

1. 快速找一句可复制的开头或结尾；
2. 按关系、情绪、语言筛选表达；
3. 阅读一封公开信及其背景；
4. 通过专题理解某类书信表达方式；
5. 从短句跳转到来源信件，确认语境和出处。

---

## 3. 范围边界

第一版只做静态内容产品，不做社区、工具平台或后台系统。

明确不做：

1. 用户登录、注册、个人中心；
2. 用户上传、投稿、评论、收藏；
3. AI 写作、AI 改写、AI 聊天；
4. 后台管理系统和在线审核流程；
5. 数据库、服务器 API、对象存储；
6. Excel / CSV 导入功能或面向运营的导入后台；
7. OCR、文件解析、用户隐私数据处理；
8. 复杂权限和多角色工作流。

内容数据由 Codex 负责研究、整理、结构化和维护。网站本身只消费已经整理好的 JSON / MDX 数据，不提供给用户或运营人员的导入界面。

首版内容只采用“公版公开信 + 本站整理”。不发布原创书信，不发布现代仿写，也不把整理、翻译、白话解释包装成历史原文。

## 6. 页面需求

### 6.1 首页

目标：让用户快速理解产品气质，并进入最常用的内容路径。

内容模块：

1. 品牌首屏：产品名、简短定位、主搜索入口；
2. 今日开头、今日结尾、今日一封信；
3. 按关系浏览：爱情、亲情、友情、师生、同袍、告别等；
4. 按表达浏览：思念、问候、致谢、歉意、祝福、告别等；
5. 专题推荐；
6. 关于尺素与内容原则入口。

### 6.2 开头馆与结尾馆

目标：快速找到可直接使用的书信表达。

功能：

1. 默认展示精选短句；
2. 支持关键词搜索；
3. 支持关系、情绪、语言、来源类型筛选；
4. 支持复制短句；
5. 支持跳转短句详情；
6. 支持跳转来源信件；
7. 空结果时给出可行动提示，而不是只显示“无结果”。

### 6.3 情谊分类页

目标：按写信对象和关系组织内容。

每个分类页展示：

1. 分类说明；
2. 推荐开头；
3. 推荐结尾；
4. 相关公开信；
5. 相关专题；
6. 常见搜索词或表达标签。

### 6.4 世界书信馆

目标：展示公开信件精选，建立内容厚度和可信感。

列表字段：

1. 标题；
2. 作者；
3. 收信人；
4. 年代或写作时间；
5. 语言；
6. 关系；
7. 标签；
8. 版权状态。

### 6.5 书信详情页

目标：提供可阅读、可引用、可溯源的完整内容。

展示内容：

1. 标题、作者、收信人、日期、语言、关系；
2. 背景说明；
3. 原文；
4. 译文或整理版本；
5. 开头摘录、结尾摘录、正文佳句；
6. 相关短句；
7. 来源链接、授权状态和版权说明；
8. 相关信件和专题。

### 6.6 短句详情页

目标：承接 SEO 长尾搜索，并让用户理解一句话的使用语境。

展示内容：

1. 原文；
2. 翻译；
3. 白话解释；
4. 现代改写；
5. 适用场景；
6. 关系标签、情绪标签、语言标签；
7. 来源信件；
8. 相关短句；
9. 复制操作。

### 6.7 专题页

目标：用编辑型内容串联短句、信件和搜索需求。

第一批专题方向：

1. 古人如何写“我想你”；
2. 英文情书如何开头；
3. 家书中的“勿念”；
4. 朋友久别后的第一句话；
5. 信的结尾，如何说不完；
6. 写给老师的敬意；
7. 战地书信里的保重；
8. 公开信中的锋芒；
9. 文学家之间的信；
10. 父母与子女之间的信。

## 7. 内容策略

内容由 Codex 负责研究、整理和结构化，输出可直接进入项目的数据文件与页面内容。

内容类型：

1. 公版公开信；
2. 开放授权文本；
3. 合理短引用；
4. 本站基于来源文本的整理、摘录、翻译和白话解释。

内容质量要求：

1. 每条内容必须有来源说明或本站整理说明；
2. 历史原文、翻译、整理、白话解释必须区分；
3. 不确定版权的内容不发布；
4. 不确定出处的内容不作为事实性公开信发布；
5. 每条短句都应能回答“适合什么关系、什么情绪、什么场景”；
6. 每封信都应能提供背景、来源和可摘录片段。

版权状态：

```text
PublicDomain：公版
OpenLicensed：开放授权
Quotation：短引用
SiteCuration：本站整理
Unknown：未知，不发布
```

## 8. UI/UX 方向

整体体验关键词：

```text
克制
清澈
文学感
可阅读
可检索
低干扰
```

视觉原则：

1. 内容优先，不做营销型大面积装饰；
2. 首屏可以有品牌气质，但必须立即提供搜索和内容入口；
3. 使用温润但不过度复古的色彩，避免整站单一米色、棕色或紫色；
4. 正文阅读宽度控制在舒适范围，桌面端不做满屏长段落；
5. 卡片只用于短句、信件、专题等重复内容，不把页面区块层层卡片化；
6. 图标统一使用同一套矢量图标，不使用 emoji 作为结构性图标；
7. 交互元素有清晰 hover、focus、pressed、disabled 状态；
8. 移动端优先保证搜索、筛选、复制和阅读效率。

关键交互：

1. 搜索输入应在首页和列表页明显可见；
2. 筛选条件可组合，并提供清除入口；
3. 复制成功要有短暂反馈；
4. 短句卡片必须能区分“复制”和“查看详情”；
5. 详情页应提供返回列表或继续浏览相关内容的路径；
6. 空状态要给出推荐关键词或重置筛选操作。

可访问性要求：

1. 正文最小字号不低于 16px；
2. 文本对比度满足 WCAG AA；
3. 所有按钮和链接支持键盘访问；
4. focus 状态必须可见；
5. 图标按钮必须有可访问名称；
6. 不依赖颜色单独表达状态；
7. 尊重 `prefers-reduced-motion`。

## 11. 成功标准

MVP 成功标准：

1. 用户能在 10 秒内理解网站用途；
2. 用户能通过搜索或筛选找到可用短句；
3. 用户能一键复制短句并看到反馈；
4. 每条公开内容都有来源和版权说明；
5. 短句详情、信件详情和专题页可被搜索引擎收录；
6. 移动端阅读和筛选体验稳定；
7. 站点无需数据库、后台、登录或导入系统即可维护；
8. 内容数据可由 Codex 持续研究、整理并直接提交到项目。
